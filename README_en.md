# AutoDL_MIA: Membership Inference Attack (MIA) on Code Completion Models

This directory provides a reproducible Membership Inference Attack (MIA) experimental pipeline targeting autoregressive code completion models (Causal LM / CodeGPT style) to evaluate the privacy leakage risks of their training samples.

## Capabilities

- **Target & Shadow Model Training**: Trains causal language models.
- **Multi-dimensional Feature Extraction**: Statistical features (Loss/PPL/Entropy, etc.) + AST structural features + LiRA differences + Embedding pooling features.
- **Attack Model Training & Evaluation**: RandomForest / XGBoost / LogisticRegression + Threshold baselines.
- **High-Security Metrics**: TPR @ 1% FPR, TPR @ 0.1% FPR.
- **Paper Plot Generation**: ROC (including log-scale), PR, TPR@lowFPR bar charts, DET, threshold diagnostic curves, confusion matrices, and Top-K feature importance.
- **Few-shot & Explainable Evaluation**: FeS-style few-shot attack training, generating Log-MIA reports (sample-level scores + low FPR calibration thresholds).

For a detailed step-by-step reproduction guide and FAQs, see: [User Reproduction Guide (Chinese)](./用户指导复现手册.md)

## Quick Start

Enter `AutoDL_MIA/` in a Linux GPU environment (AutoDL / Ubuntu 22.04 + CUDA recommended):

```bash
pip install -r requirements.txt
bash run_all.sh
```

**Few-shot mode** (for resource-constrained environments / quick privacy checks):

```bash
MIA_MODE=fes bash run_all.sh
```

*Note*: When `NUM_SHADOW_MODELS=1`, LiRA-related features will degrade (reference model is empty). This implementation sets LiRA difference features to 0 to avoid NaNs. If you want effective LiRA features, it's recommended to set `NUM_SHADOW_MODELS>=2`.

## Key Scripts

- `prepare_mia_data.py`: Downloads Concode and strictly partitions Target/Shadow datasets.
- `train_target_model.py`: Trains the target model (Causal LM).
- `train_shadow_models.py`: Trains multiple shadow models (Causal LM).
- `extract_features.py`: Extracts attack features (Stats + AST + Embedding + LiRA).
- `mia_pipeline/cli.py`: Attack evaluation entry point (classic / fes) and Log-MIA report generation.
- `run_all.sh`: One-click pipeline (supports skipping stages).

## Output Artifacts

- `mia_data/`, `mia_data_raw/`: Dataset caches.
- `models/target_model/`, `models/shadow_model_*/`: Trained models.
- `attack_train_dataset.csv`, `attack_test_dataset.csv`: Attack training/testing feature tables.
- `plots/main_models/`: Main experiment plots and `metrics_table.csv`.
- `plots/ablation/`: Ablation plots (if generated using the corresponding script).
- `plots/main_models/logmia_*.{csv,json,md}`: Log-MIA reports (generated by default in few-shot mode).

## GitHub Note

A `.gitignore` is provided in the repository root, which defaults to ignoring training artifacts (`models/`, `mia_data*/`, `plots/`, etc.) and intermediate CSVs to prevent pushing large files to GitHub by mistake.

## Reproduction Switches (run_all.sh)

Stage skipping (value `1` means skip):

- `SKIP_INSTALL`: Skips `pip install`
- `SKIP_DATA`: Skips data preparation
- `SKIP_TRAIN_TARGET`: Skips target model training
- `SKIP_TRAIN_SHADOW`: Skips shadow model training
- `SKIP_EXTRACT`: Skips feature extraction
- `SKIP_ATTACK`: Skips attack evaluation and plotting

Example: Feature CSVs already exist, only rerun attack evaluation:

```bash
SKIP_INSTALL=1 SKIP_DATA=1 SKIP_TRAIN_TARGET=1 SKIP_TRAIN_SHADOW=1 SKIP_EXTRACT=1 bash run_all.sh
```

Example: Only rerun attack evaluation and generate Log-MIA in few-shot mode:

```bash
SKIP_INSTALL=1 SKIP_DATA=1 SKIP_TRAIN_TARGET=1 SKIP_TRAIN_SHADOW=1 SKIP_EXTRACT=1 MIA_MODE=fes bash run_all.sh
```

## FAQ

- `RuntimeError: xgboost is not installed but requested`: Install `xgboost` or remove `xgb` from `ATTACK_MODELS`, e.g., `ATTACK_MODELS=rf,thr_loss`.
- Slow/failed downloads in mainland China: The scripts default to `HF_ENDPOINT=https://hf-mirror.com`. If you have direct access to HuggingFace, you can remove this line in the scripts.
